# PRD — Flow 나노바나나2 에이전트 대량 생성 워크플로우

작성: 2026-11-12 · 형태: 앱(GUI) 없음. **절차 문서(스킬) + 보조 스크립트**로 구성하고 에이전트(Claude)가 실행한다.

## 1. 목표
- Google Flow(`https://flow.google.com/`)의 무료 모델 **Nano Banana 2.1**로 이미지를 대량 생성한다(계정 1개, 하루 한도 안).
- 반복 구간은 스크립트가 컴퓨터 자원으로 처리하고, AI 토큰은 기획(캐릭터 시트·프롬프트 설계)과 몽타주 기반 최종 판정에만 쓴다.
- 일관성 확보, 품질 상승, 이미지 수정을 같은 루프에서 처리한다.

## 2. 비목표
- GUI 앱, 크롬 웹스토어 배포, 여러 계정 순환, Flow 내부 API 직접 호출, 동영상(Veo) 생성.
- 라핀 확장 코드 재사용(수정 금지 라이선스·난독화). 원리만 참고한다.

## 3. 조사로 확인한 사실 (2026-11-12, 실제 로그인 계정에서 측정)
| 항목 | 결과 |
|---|---|
| 접근 | Aside 브라우저(로그인 유지)에서 `aside repl` 스크립트로 조작 가능, 단계별 LLM 호출 없음 |
| 입력 | `textbox "무엇을 만들고 싶으신가요?"`에 `insertText` → `button "생성 시작"` 클릭 |
| 설정 | `button "설정 트리거"` 패널: 이미지/동영상, 비율 16:9·4:3·1:1·3:4·9:16, 장수 x1~x4, 모델 선택(Nano Banana 2.1 크레딧 0 표시). 라디오는 `role=radio` 버튼이며 Playwright `check`가 아닌 DOM `click()`으로 선택해야 함 |
| 속도 | x2 1회 약 26초. x1 프롬프트 3개를 5초 간격으로 연속 제출 → 26·28·36초에 모두 완료(병렬 처리됨) |
| 참조·수정 | 타일 메뉴 `프롬프트에 추가` → 입력창에 `소재` 이미지가 붙음 → 수정 프롬프트로 생성 32초. 같은 피사체 유지 확인 |
| 결과 감지 | `img[alt="사용자 이미지를 표시하는 타일"]` 개수 증가, 상위 `role=group`의 `aria-label`이 자동 제목 |
| 다운로드 | 타일 `옵션 더보기` → `다운로드` → `1K 원본 크기`(1:1 기준 1024×1024 JPEG), `2K 업스케일링됨` 가능, `4K` 비활성. 화면 썸네일은 512px webp라 수집에 쓰지 않음 |
| 보관 | 상단 공지 "가장 오래된 제작물이 곧 만료됩니다" → 생성 직후 로컬로 받아야 함 |
| 오류 문구 | 이번 측정에서는 한도·오류 메시지가 나오지 않아 문구 미확인 |

공개 자료: MIT 라이선스 `ParkSangGwon/google-flow-mcp`(2026-09 갱신), `swissmarley/gflow-cli`(2026-06 갱신)는 둘 다 실제 Chrome에 Playwright `connectOverCDP`로 붙어 Flow 화면을 조작한다. Google은 원격 디버깅이 켜진 브라우저에서 로그인을 막으므로, 로그인은 일반 크롬에서 하고 같은 프로필을 디버그 포트로 다시 연다. 한도 수치(무료 일 400장 등)는 2차 출처라 공식 확인이 필요하다.

## 4. 구성
```
spec.yaml (Claude 작성) → compose → prompts.jsonl
prompts.jsonl → flow_run (브라우저 조작·다운로드) → out/<run>/images + manifest.json
out/<run> → check (해상도·빈 이미지·중복) → montage → Claude 판정 → redo.jsonl → flow_run
```
| 도구 | 역할 | 토큰 |
|---|---|---|
| `compose` | spec(캐릭터 시트·고정 스타일 블록·장면 변수)을 프롬프트 목록으로 조합 | 없음 |
| `flow_run` | 설정(비율·장수·모델) 적용, 프롬프트 연속 제출, 완료 감지, 1K/2K 다운로드, 참조 이미지 붙이기, manifest 기록, 재실행 시 끝난 항목 skip | 없음 |
| `check` | 해상도·파일 손상·단색/빈 이미지·근사 중복(perceptual hash) 검사, PASS/FAIL JSON | 없음 |
| `montage` | 번호가 찍힌 축소 그리드 이미지 생성 | 없음 |
| 스킬 문서 | 에이전트 절차: 기획 → 실행 → 검사 → 몽타주 판정 → 재생성·수정 | 판정에만 |

브라우저 실행기: **1차는 `aside repl` 스크립트**(지금 로그인 상태로 검증 완료). 이미지 파일은 Aside 세션 폴더가 호출 종료 시 사라지므로 다운로드 바이트를 표준출력(base64)으로 넘겨 Python이 저장한다. Aside가 불안정하면 같은 셀렉터를 쓰는 Playwright `connectOverCDP`(전용 크롬 프로필) 실행기로 교체한다. 셀렉터는 한 파일에 모아 화면 변경 시 한 곳만 고친다.

## 5. 일관성·품질·수정
- 일관성: 캐릭터마다 기준 이미지 1장을 확정하고 `프롬프트에 추가`로 매번 참조로 붙인다. 고정 스타일 블록과 시드 성격의 문구(조명·렌즈·팔레트)를 spec에서 강제한다.
- 해상도(실측): 1K 원본은 1:1 1024×1024, 16:9 1376×768로 1080에 못 미친다. 2K 업스케일은 1:1 2048×2048, 16:9 2752×1536(장당 약 16초). 1080 규격(1080×1080·1920×1080·1080×1920)이 필요하면 2K로 받아 스크립트로 정확히 축소한다.
- 품질: 기본은 1K 원본 다운로드, 1080 이상이 필요한 장만 2K 업스케일 다운로드. 장면당 x2~x4로 뽑고 몽타주에서 최선 1장을 고른다.
- 수정: 불합격 장면은 원본을 참조로 붙여 수정 프롬프트로 재생성(측정 32초).

## 6. 차단 회피 운영 규칙
- 계정 1개, 사용자가 로그인한 실제 브라우저에서만 실행. 내부 API 호출 없음.
- 제출 간격 무작위 5~12초, 동시 진행 최대 3~4건, 30~40건마다 1~3분 휴식.
- 하루 목표는 한도의 약 70%(초기값 280장)로 시작, 실사용 결과로 조정.
- 오류·한도·캡차·로그인 화면이 보이면 즉시 정지하고 manifest에 기록, 자동 재시도는 1회까지.

## 7. 산출물 형식
- `artifacts/runs/<YYYYMMDD-HHMMSS>-<작업명>/`: `prompts.jsonl`, `images/<id>_<n>.jpg`, `manifest.json`(id·프롬프트·설정·생성 시각·파일·상태), `check.json`, `montage_*.jpg`.
- 원본은 덮어쓰지 않고 수정본은 `_2`, `_3` 번호를 붙인다.

## 8. 수용 기준
- 프롬프트 30개 이상 배치가 사람 개입 없이 끝나고, 성공률 95% 이상, 평균 장당 처리 시간 측정치가 manifest에 남는다.
- 재실행 시 이미 받은 항목을 다시 생성하지 않는다.
- 캐릭터 참조 배치에서 몽타주 판정 일관성 합격률 80% 이상.
- 각 스크립트 `--self-test` PASS.

## 9. 미확인·위험
- 한도 초과·오류·캡차 화면의 실제 문구(실전 배치에서 수집해 정지 조건에 반영).
- 무료 일일 한도의 정확한 수치.
- Flow 화면 변경 시 셀렉터 수정 필요(한 파일로 격리).
- Aside REPL 호출마다 탭이 새로 열리므로 배치는 한 번의 호출 안에서 끝내야 함(긴 배치는 분할 실행).
